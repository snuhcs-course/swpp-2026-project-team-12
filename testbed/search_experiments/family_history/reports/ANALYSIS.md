# 가족 추억 찾기 — 결과 해석과 대표 실패

본실험 540건 및 채점 완료. 30문항 × 3규모 × 2방식 × 3회이며, 예비 20건은 본실험에서 제외했다. 공유 앱 코드와 세 Neo4j 그래프의 전체 속성·임베딩 fingerprint는 동일했다.

## 결론

- Graphiti는 Full History 대비 생성 토큰을 100/200/300개 규모에서 각각 **83.6% / 91.4% / 94.1% 절약**했다.
- 자동 채점 정확도는 Full **97.8% / 100.0% / 97.8%**, Graphiti **98.9% / 93.3% / 91.1%**였다. 200·300개에서는 Graphiti가 각각 6.7%p 낮았다.
- Graphiti 오답 15건 중 12건은 인버터 결제 관련 두 질문(HQ09/HQ26)에 집중됐다. 나머지 3건은 모모 밥 시간과 담당자를 연결하면서 현재 시간 적용을 유보한 HQ23이다.
- Full 오답 4건은 HQ23 3건, HQ01 1건으로 모두 시간 적용을 유보한 답변이다. 이런 표현의 실패 판정은 해석 여지가 있어 원문과 채점 이유를 함께 보존했다.
- 토큰 절약은 뚜렷하지만 일관된 속도 우위는 확인하지 못했다. 평균은 200·300개에서 Graphiti가 낮았으나 중앙값은 세 규모 모두 Full이 조금 낮았다. 서버 변동·캐시·응답 길이의 영향이 포함된다.

## 대표 사례

### 1. 저장된 최신 결제 사실이 검색에서 누락됨

- 질문 HQ09: “도윤이가 결제한 공구는 뭐야?”
- 정답: RYOBI 150W 인버터.
- 필요한 기록 `M04-4`: “RYOBI 150W 인버터만 오늘 결제했어! 고압 세척기는 안 사기로 하고 장바구니에서 뺐다.”
- 옛 기록 `M04-1`: 장바구니에 담았지만 아직 결제하지 않음. `M04-3`: 두 공구 모두 고민 중.
- 100개 Graphiti: 3/3 정답. 200·300개: 각각 0/3. Full은 세 규모 모두 3/3.
- 200개 Graphiti는 다른 회전 공구·정리 글 등을 검색하고 “결제한 공구는 확인되지 않는다”고 답했다. 300개에서는 옛 장바구니 기록을 받아 “아직 결제하지 않았다”고 답한 사례도 있다.
- **저장 누락이 아님:** 세 그래프 모두 `M04-4` Episode와 “도윤은 인버터만 결제했다”는 유효한 Fact가 존재한다. 이 Fact는 `invalid_at`과 `expired_at`도 없다. `output/inverter_storage_audit.json`에 대조 결과를 저장했다.
- 원인 범위: 검색 후보 순위/선택에서 필요한 기록이 빠진 것. 질문 자체로 한 번 검색하는 가족 추억 찾기 경로의 문제이며 Post QA의 `select_budget()` 문제가 아니다.
- HQ26(도윤의 구매 공구와 철수의 구매 공구를 함께 질문)도 같은 결제 근거 누락으로 200·300개에서 각 3회 실패했다.

### 2. 근거는 확보했지만 시간·담당자 연결을 유보함

- 질문 HQ23: “10월 17일 기준 모모의 아침밥은 누가, 몇 시에 챙기기로 했어?”
- 정답: 지민, 아침 8시.
- `M01-2`: “모모 밥은 아침 8시에 한 번 줘요.”
- `M01-4`: 지민이 오늘부터 밥을 맡기로 함. `M01-6`: 지민이 아침밥을 챙기고 있다는 확인.
- 두 방식 모두 필요한 기록을 받았지만 “8시라는 기록은 있으나 지민이 맡은 뒤에도 같은 시간인지 확인되지 않는다”고 답한 사례가 있다.
- 원인 후보: 현재 시점과 기록 유효기간을 엄격히 비교하도록 한 프롬프트가, 시간 변경 근거가 없는 상황에서도 지속 여부를 유보하게 만든다. 검색 누락과는 구분해야 한다.
- 정답표는 담당자 변경이 시간 변경을 뜻하지 않는다고 미리 정했다. 다만 핵심 시간 자체를 말한 뒤 유보하는 답변의 판정은 경계 사례다. 점수는 수정하지 않았다.

### 3. 답은 맞지만 표시한 게시글이 틀림

- 사례 `full-100-HQ17-full_history-2`.
- 질문: “옆집 철수가 샀다는 공구는 뭐야?”
- 답변: Hyper Tough 고압 세척기 — 정답.
- 실제 근거 `M04-5`: “옆집 철수는 Hyper Tough 고압 세척기 샀대~ 우리 건 아니고.”
- 표시 출처 `B033`: “가방 정리 끝~” — 무관한 글.
- 앱은 존재하는 출처 ID인지 검사하므로 이 ID는 정상 연결되지만, 의미상 정답 출처는 아니다. Answer Accuracy와 Citation Sufficiency를 따로 측정해야 하는 이유다.

### 4. 정보 없음에는 잘 답하지만 빈 출처 규칙은 지키지 않음

- 정보 없음 4문항의 답변 정확도는 두 방식 모두 36/36이다.
- 하지만 HQ30 “인버터 주문번호가 뭐야?”에는 “주문번호는 확인되지 않는다”고 답하면서 결제 게시글을 붙이는 경우가 반복됐다.
- 빈 출처 반환은 두 방식 모두 27/36 = 75%. 답변의 사실성 실패와 출력 규칙 위반을 구분한다.

## 자동 채점 검수에서 발견한 한계

원래 모델 판정과 점수는 수정하지 않았다. 아래 항목은 별도 검수 메모이며, 독립된 사람의 최종 판정은 아직 없다.

1. **Memory Update Error 자동 판정은 해석 보류.** `full-300-HQ09-graphiti-1`은 “아직 결제하지 않으셨어요”라고 현재 상태를 잘못 말했지만 `memory_update_error=false`로 채점됐다. 따라서 자동 집계 0%를 “기억 갱신 오류가 없다”는 근거로 쓰면 안 된다. 200개 사례처럼 단순히 확인 불가라고 한 경우와 구분해 사람 검수가 필요하다.
2. **부수적 허구 판정은 입력 한계가 있음.** 채점기는 정답 사건의 원문과 최종 표시 게시글을 보지만 검색된 모든 미표시 기록을 보지는 않는다. `full-200-HQ09-graphiti-1`의 Dremel 언급을 근거 없음으로 봤으나 실제 검색 문맥에는 관련 설명이 있다. 이 한계는 `no_material_false_additions`와 strict accuracy에 영향을 줄 수 있다. 주 지표는 질문의 정답 충족률로 보고한다.
3. **유보 표현 판정의 경계 사례.** HQ01/HQ23처럼 아침 8시를 말하고도 현재 적용은 확인 불가라고 하는 답변의 정오에는 해석 여지가 있다. 판정 근거를 공개하고 비교 점수를 확정된 사람 평가처럼 표현하지 않는다.
4. **ID Recall은 충분성의 완전한 대체 지표가 아님.** HQ25는 새 선생님 변경 글 대신 “서연 선생님의 두 번째 수업” 글로 답할 수 있다. 정답 ID 조합이 빠져도 의미상 충분한 출처일 수 있어 Citation Sufficiency를 함께 보고한다.

## 범위

기존 4인 합성 가족의 명시적 사실·변경 기록·출처 게시글 찾기 평가다. 원본 MemoryQA 정답이나 자연 발생 가족 대화 전체에 대한 점수가 아니다. 사진은 과거에 생성한 설명으로 표현했고 이번 호출에는 사진을 보내지 않았다. 얼굴 인식·사진 자체 이해·넓은 의미의 사진 모음 검색·HTTP/worker/UI/TTS는 별도 평가 대상이다.

세 규모의 그래프는 이전에 각각 구축됐으므로 추출된 Fact가 정확히 같은 부분집합인 것은 아니다. 규모별 차이에는 기록 증가와 그래프 구성 차이가 함께 반영될 수 있다. 같은 질문을 3회 반복한 것이므로 270개 독립 질문으로 해석하지 않는다.

## 후속 실험 후보

우선 HQ09/HQ26에서 필요한 결제 Fact와 Episode가 검색 상위 결과에 들어오도록 검색 후보 수·질문 표현을 비교하는 것이 타당하다. 현재 질문에 정답 단어인 “RYOBI”를 임의로 넣으면 정답 누출이 되므로, 사용자 질문에서 생성 가능한 검색어만 사용해야 한다. 이번 실험에서는 앱이나 프롬프트를 수정하지 않았다.
